# data/

All data artifacts produced and consumed by the RAG pipeline, plus the application database and source PDFs.

> **What's committed vs generated:**
> - **Committed (in git):** `*.pdf` source documents only
> - **Generated (gitignored):** everything else — re-created by `python main.py pipeline`
> - **Runtime (gitignored):** `uploads/`, `app.db`

---

## Directory Layout

```
data/

├── Road Safty (English) New Book.pdf  # Source PDF 2 (vector-path, 89 pages, OCR)

├── extracted/                         # Step 1 output — one .txt per PDF
│   ├── TN traffic rules.txt
│   └── Road Safty (English) New Book.txt
│

│
```

## Source PDFs

Any `*.pdf` file placed directly in `data/` is automatically picked up by `python main.py pipeline`. The pipeline processes them in alphabetical order and builds a single unified index.

| File | Pages | Extraction method | Chunks |
|------|-------|-------------------|--------|
| `Road Safty (English) New Book.pdf` | 89 | OCR (Tesseract) — text stored as vector paths | 139 |
| `TN traffic rules.pdf` | 60 | Direct (PyMuPDF) — embedded text | 351 |
| **Total** | **149** | | **490** |

To add more PDFs: copy them into `data/` and re-run `python main.py pipeline`.

---

## extracted/

One plain-text file per source PDF, generated by `src/extractor.py`. Each file has page markers in the format `--- Page N ---` to preserve page boundaries.

Files are named `<pdf_stem>.txt` — e.g. `TN traffic rules.pdf` → `TN traffic rules.txt`.

These files are intermediate artifacts; the pipeline reads them to produce chunks. They can be inspected to verify extraction quality before re-indexing.

---

## chunks/

Individual semantic chunk files produced by `src/chunker.py`. Each file contains one self-contained section of text, split at the document's own numbered headings (`4. Title`, `4.1 Sub`, `4.1.1 Detail`).

- File names are zero-padded: `chunk_0000.txt` through `chunk_0489.txt`
- Chunks are ordered: first all chunks from PDF 1, then all from PDF 2 (alphabetical)
- Soft size limit: **350 words** per chunk; oversized sections split on paragraph boundaries
- The mapping of chunk index → source PDF is stored in `embeddings/chunk_sources.json`

---

## embeddings/

### `embeddings.npy`
NumPy binary array of shape `(490, 384)`, dtype `float32`. Each row is the embedding of the corresponding chunk file, produced by the `all-MiniLM-L6-v2` sentence-transformer model. Kept alongside the FAISS index for merging when new PDFs are added via the web UI.

### `faiss_index.bin`
Serialised `IndexFlatL2` FAISS index. Loaded once at startup and used for all semantic similarity searches. The BM25 index (for keyword search) is rebuilt in-memory from the chunk files at load time and is not stored on disk.

### `chunk_sources.json`
JSON object mapping every chunk index (as a string) to the name of the PDF it came from:

```json
{
  "0": "Road Safty (English) New Book.pdf",
  "138": "Road Safty (English) New Book.pdf",
  "139": "TN traffic rules.pdf",
  "489": "TN traffic rules.pdf"
}
```

Used by `src/indexer.py` when adding new PDFs at runtime (to append new entries without overwriting existing ones), and by `get_indexed_docs()` to show users what's in the knowledge base.

---

## uploads/

PDFs uploaded through the web UI sidebar (📚 Knowledge Base → "Add a PDF"). Files are saved here, processed immediately, and merged into the existing FAISS index via `src/indexer.py` — no pipeline re-run required.

Uploaded documents are tracked in `chunk_sources.json` alongside pipeline-indexed documents. They persist across server restarts since the index files are updated on disk.

---

## app.db

SQLite database created automatically when `app.py` first starts. Never overwritten by the pipeline.

| Table | Contents |
|-------|----------|
| `users` | Registered accounts — `id`, `username` (unique), `password_hash`, `created_at` |
| `chat_sessions` | One row per conversation — `id`, `user_id`, `title`, `created_at` |
| `messages` | All messages — `id`, `session_id`, `role` (`user`/`assistant`), `content`, `created_at` |

**Inspect directly:**
```bash
sqlite3 data/app.db ".tables"
sqlite3 data/app.db "SELECT username, created_at FROM users;"
sqlite3 data/app.db "SELECT title, created_at FROM chat_sessions ORDER BY created_at DESC LIMIT 10;"
```

## Regenerating Artifacts

Re-run the pipeline at any time to re-process all PDFs from scratch:

```bash
python main.py pipeline
```

This clears and rewrites: `extracted/`, `chunks/`, `embeddings/`. It does **not** touch `app.db`, `uploads/`, or the source PDFs.

Adding a new PDF:
```bash
# Option A — batch (re-indexes everything)
cp new_doc.pdf data/
python main.py pipeline

# Option B — live (no pipeline re-run, merges into existing index)
# Use the web UI sidebar: 📚 Knowledge Base → upload PDF → "Index PDF"
```
