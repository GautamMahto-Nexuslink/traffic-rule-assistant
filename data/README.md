# data/

This directory holds all data artifacts produced and consumed by the RAG pipeline, as well as the application database.

> **Note:** Most files here are generated — only `TN traffic rules.pdf` and `app.db` are persistent. Re-running `python main.py pipeline` will regenerate everything else.

---

## Directory Layout

```
data/
├── TN traffic rules.pdf      # Source document (input — do not delete)
├── extracted_text.txt         # Plain text extracted from the PDF (Step 1 output)
├── chunks/                    # Overlapping text chunks (Step 2 output)
│   ├── chunk_0000.txt
│   ├── chunk_0001.txt
│   └── ...
├── embeddings/                # Vector artifacts (Step 3 output)
│   ├── embeddings.npy         # NumPy array — shape: (N, 384), float32
│   └── faiss_index.bin        # FAISS IndexFlatL2 binary
└── app.db                     # SQLite database — users + chat history
```

---

## File Descriptions

### `TN traffic rules.pdf`
The official Tamil Nadu traffic rules document. This is the only manually placed input file. All other artifacts are derived from it by the pipeline.

---

### `extracted_text.txt`
Raw text output from PyMuPDF, with page markers in the format `--- Page N ---`. Generated by `src/extractor.py` during Step 1.

---

### `chunks/chunk_XXXX.txt`
Individual text chunks produced by `src/chunker.py` during Step 2. Each file contains approximately **400 words** of content with an **80-word overlap** from the previous chunk to preserve context across boundaries. Files are zero-padded and sorted lexicographically (e.g. `chunk_0000.txt`, `chunk_0001.txt`).

The number of chunks depends on the document size. For the current PDF:
- **44 chunks** from 60 pages / 105,551 characters

---

### `embeddings/embeddings.npy`
A NumPy binary array of shape `(N, 384)` where `N` is the number of chunks. Each row is the `float32` embedding of the corresponding chunk produced by the `all-MiniLM-L6-v2` sentence-transformer model.

---

### `embeddings/faiss_index.bin`
A serialised FAISS `IndexFlatL2` binary index containing all `N` chunk vectors. Used at query time to retrieve the **top-5** most semantically similar chunks for a given user question.

Both `embeddings.npy` and `faiss_index.bin` are generated together by `src/embedder.py` during Step 3. The `.npy` file is not needed at query time (only the FAISS index is loaded), but is kept for inspection or reuse.

---

### `app.db`
SQLite database created automatically on the first launch of `app.py`. Contains three tables:

| Table | Contents |
|-------|----------|
| `users` | Registered user accounts (username + hashed password) |
| `chat_sessions` | One row per conversation, linked to a user |
| `messages` | All chat messages (role + content), linked to a session |

To inspect the database directly:
```bash
sqlite3 data/app.db ".tables"
sqlite3 data/app.db "SELECT username, created_at FROM users;"
```

---

## Regenerating Artifacts

If you replace the source PDF or want to re-process:

```bash
python main.py pipeline
```

This will overwrite `extracted_text.txt`, all files in `chunks/`, and both files in `embeddings/`. The `app.db` and existing chat history are **not affected**.
